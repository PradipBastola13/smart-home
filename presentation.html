Port Allocation & Networking Architecture (Key Concept)

Host Machine (Single IP: 192.168.1.73): Runs three independent server services sharing one network interface, requiring distinct port numbers for traffic routing:

  • React Dashboard: Port 5173
  • Spring Boot REST API: Port 8080
  • PostgreSQL Database: Port 5432

ESP32 Node (Independent IP): An autonomous hardware client with its own separate Wi-Fi IP address. It functions as an HTTP Client—actively initiating outbound requests to Spring Boot on port 8080 rather than hosting an internal server.

Slide 3: Core REST APIs (The Communication Hub)

The Spring Boot backend exposes dual-purpose REST endpoints designed for two distinct clients:

Method Route Request Body Response Format Caller Purpose & Rationale
GET /api/devices None JSON Array React Fetches full device state for dashboard rendering.
POST /api/devices/{id}/toggle None JSON Object React Flips device power state (ON/OFF) and updates PostgreSQL.
GET /api/devices/{id}/state None Plain Text ("ON" / "OFF") ESP32 RAM-Optimized: Raw text avoids JSON parsing on the microcontroller.
POST /api/devices/{id}/heartbeat None { "status": "success" } ESP32 Liveness probe: Records current timestamp in PostgreSQL.

Slide 6: Key Java Backend Code & Business Logic

1. REST Controller (DeviceController.java)

@RestController
@RequestMapping("/api/devices")
public class DeviceController {
    private final DeviceService deviceService;

    // Constructor Injection (Spring IoC / DI)
    public DeviceController(DeviceService deviceService) {
        this.deviceService = deviceService;
    }

    @PostMapping("/{id}/toggle")
    public ResponseEntity<Device> toggle(@PathVariable Long id) {
        return deviceService.toggleDevice(id)
                .map(ResponseEntity::ok)
                .orElse(ResponseEntity.notFound().build());
    }

    @GetMapping("/{id}/state") // Plain text for ESP32
    public ResponseEntity<String> getStateRaw(@PathVariable Long id) {
        return deviceService.getDeviceById(id)
                .map(d -> ResponseEntity.ok(d.getIsOn() ? "ON" : "OFF"))
                .orElse(ResponseEntity.notFound().build());
    }
}

2. Dynamic Liveness Property (Device.java)

@JsonProperty("online")
public boolean isOnline() {
    if (lastHeartbeat == null) return false;
    // Evaluated dynamically at serialization time:
    return Instant.now().minusSeconds(15).isBefore(lastHeartbeat);
}

Slide 7: Database Storage (PostgreSQL 18)

The devices Relational Table:

 id | is_on |          last_heartbeat          |       name        |  type  
----+-------+----------------------------------+-------------------+--------
  1 | t     | 2026-09-09 13:25:33.964334+05:45 | Living Room Light | Switch

Key Technical Highlights:

  • Data Fields:
    • id: Auto-generated primary key.
    • is_on: Boolean (t = ON, f = OFF).
    • last_heartbeat: Timestamp of the last received hardware ping.
  • Spring Data JPA: Interface DeviceRepository extends JpaRepository<Device, Long> automatically provides all CRUD methods without boilerplate SQL code.
  • Data Durability: Device states survive server and laptop restarts.

Slide 8: Live Demonstration & Future Improvements

System Initialization Commands (Live Demo Cheat-Sheet):

  • One-Click Launcher: Double-click start-demo.bat (launches both Backend & Frontend in separate windows).
  • Start Backend: cd backend && .\mvnw.cmd spring-boot:run (Port 8080)
  • Start Frontend: npm run dev (Port 5173)
  • Database Check: Get-Service *postgres* (Runs automatically as service on Port 5432)
  • Free Port 8080 (If busy): Stop-Process -Name java -Force

Live Demonstration Protocol:

  1. Verify Online Status: Open dashboard (http://localhost:5173) showing device marked ● Online.
  2. Toggle Power State:
    • Click "Turn On" ➔ Button updates to "Turn Off".
    • PostgreSQL table updates is_on from f to t.
    • ESP32 receives "ON" and physical blue LED lights up.
  3. Simulate Disconnection: Unplug ESP32 ➔ Wait 15 seconds ➔ Dashboard badge automatically changes to ○ Offline.

Future Improvements:

  • Relay Module: Connect an AC relay module to control real 220V wall lights and fans.
  • Sensors: Add DHT11 sensor for live room temperature and humidity monitoring.
  • MQTT / WebSockets: Replace HTTP polling with real-time bidirectional push messaging.
